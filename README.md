# MiniCPM 文档解析台

一个 Windows 本地 Web 文档解析试验工具：将 PDF 或图片逐页交给 MiniCPM-OCR 1.0，结合 PP-DocLayoutV3 进行版面检测，并在浏览器中对照原页与识别结果。支持多文件、图片提取、暂停续跑、可选临时分段和完整 ZIP 导出。

**状态：研究原型，不保证所有文档解析正确。** 不提供翻译功能；复杂双栏、跨页段落、目录层级、表格、公式和图题关联需要人工核对。页面、区域坐标和版面识别都可能有误；生成式模型也可能漏字或改写原文。

## 功能

- 输入 PDF、PNG、JPG、JPEG、BMP、WebP、TIF、TIFF；有密码的 PDF 请先另存无密码副本。
- 使用 PP-DocLayoutV3 在 CPU 上检测版面，使用 llama.cpp 和 NVIDIA GPU 执行 MiniCPM-OCR 区域识别。
- 文字、表格、公式使用不同提示词；图片、图表与印章区域裁剪后保存在结果中。表格和公式输出不保证准确。
- 左侧原始页面、右侧当前页结果，按页联动；图片出现在右侧结果下方，右侧文字为 Markdown 源码。
- 支持选择是否过滤识别为页眉、页脚和页码的区域；该功能依赖模型分类，可能误删或漏删。不能根据它保证去除所有重复页眉。
- 处理时显示页码和区域，支持安全暂停、继续、按页面或按系统内存可选保存临时分段；每个识别区域和页面都会保存供续跑。
- 对 Windows 文件暂时被占用、部分模型连接错误按 5 秒重试；监督器在运行时意外退出后重启应用。真正的永久错误仍会停止并报告。
- 全部页面成功后生成完整 ZIP，包含 Markdown 和提取图片；未完成时只允许下载明确标注页码范围的临时分段。
- “运行环境与资源”显示本机 Python、依赖、GPU、显存、系统内存和模型文件状态，不会主动上传这些信息。

## 硬件与系统

- Windows 10/11 64 位，Python **3.11**（依赖锁文件基于 Windows + Python 3.11）。
- NVIDIA 显卡及合适的 CUDA 12.4 驱动；推理以 GPU 为目标，版面检测使用 CPU。请提前通过 `nvidia-smi` 确认驱动可用。没有 NVIDIA GPU、Linux、macOS、WSL、AMD 等配置未在此版本验证。
- 本项目在一台 Windows 11、RTX 4070 Laptop 8 GB 显存、16 GB 系统内存电脑上测试了实际图片与 PDF；**不保证其他电脑或所有页面都能运行**。页面大小、布局、并行度和其他程序占用会影响峰值资源。
- 首次下载的模型和运行时约 2.5 GB，另需 Python 依赖、解压空间和用户文件；建议预留至少 10 GB，处理大文档需额外空间。安装需联网，配置完成后 OCR 请求指向本机。

## 安装：独立环境

可以先克隆公开仓库：

```powershell
git clone https://github.com/Mystery-W/minicpm-ocr-document-parser.git
Set-Location .\minicpm-ocr-document-parser
```

请在 PowerShell 中进入下载或克隆的项目目录。下面只创建并修改该目录下的 `.venv`，不会修改已有 Conda 环境。推荐系统已安装 Python 3.11（`py -3.11` 可用）：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
.\.venv\Scripts\python.exe .\setup_assets.py
```

也可以运行 `setup.ps1` 执行相同流程；如果使用其他 Python 3.11 可执行文件，传入 `-Python` 指向它。基于已有 Conda 环境创建 venv 时，该 venv 可能依赖原环境的 Python 和 DLL，不能假设可直接复制到另一台机器。请不要把依赖安装到 `base` 或其他共享环境。

模型默认从 Hugging Face 下载；如果 Hugging Face 网络不畅，可选择官方 ModelScope 镜像（其他资源仍从其官方地址获取）：

```powershell
.\.venv\Scripts\python.exe .\setup_assets.py --model-source modelscope
```

脚本下载官方 Q8 GGUF、视觉投影、Paddle 版面模型及固定的 llama.cpp b11972 Windows CUDA 12.4 运行时。新下载的文件通过固定 SHA-256 校验；大文件使用 `.part` 续传，已有文件不覆盖，哈希不匹配时请先检查。已有解包目录只检查必要文件是否存在，不重新校验。首次安装后如果下载失败，可重新运行；网络代理或服务端若不支持续传也可能需要手动处理留下的 `.part`。不要下载模型的全部量化版本。

安装过程及依赖的联网行为由对应项目决定；应用页面、OCR 推理及文件处理绑定本机地址，不要求云 OCR 服务。请自行判断文献的存储和使用权限。

## 启动和使用

1. 双击 `启动.bat`，或在 PowerShell 执行 `.\.venv\Scripts\python.exe .\supervisor.py`。打开 [http://127.0.0.1:7865/](http://127.0.0.1:7865/)；终端式启动时请保持窗口打开。
2. 展开“运行环境与资源”检查 Python、依赖、GPU、模型文件和服务状态。GPU 占用是整卡瞬时值，显存总占用包括其他进程，**不是**模型专属用量；系统没有 `nvidia-smi` 时显示不可用。
3. 点击“启动 GPU 模型”，等待“模型已就绪”。选择一个或多个文件后点击“导入文件”；应用会保存副本，不覆盖源文件。
4. 可按需勾选过滤页眉页码、按页数保存分段、按系统内存保存分段。两种分段条件互不依赖；新任务默认关闭。两项都关闭时，逐页和逐区域续跑数据仍会保存，完整结果仍会生成。
5. 在左侧选择文件，点击“处理 / 继续当前文件”，或处理所有未完成文件。勾选“跟随处理页”可跟随查看正在处理的页面；手动查看其他页可取消勾选。
6. 点击“暂停当前文件”，等状态显示“已暂停”后可继续。暂停在当前区域完成或等待重试时生效；模型仍可能占用显存。继续前可修改分段条件；已有任务不能修改页眉过滤选项，否则请重新导入创建新任务。
7. 分段开启时可展开“查看和下载临时分段”；它们只是对应页码的部分结果。所有页面完成后点击“下载完整结果”；ZIP 内 `document.md` 通过相对路径引用 `images/`，解压后请保持相对位置。

## 保存、恢复及内存

`data/<任务ID>/` 保存输入副本、任务状态、逐区域检查点和逐页结果；`layout_v2/` 是版面模式目录。不要删除正在运行任务的文件。每次处理在区域和页面边界保存，重启后会跳过已成功的页面或相同的已成功区域；任务失败时未完成页不会被当作成功。进度文件和临时分段使用原子替换，并在 Windows 短暂锁定时重试。

当启用按页数分段和按内存分段时，任意条件触发都会生成从上个分段结束后的连续页面；计数从新分段开始。持续高内存时，内存触发至少间隔 5 个已完成页。启用任一条件时，结束后保存最后不足一段的尾页。阈值是**整台电脑的系统内存百分比**，保存分段不会主动释放内存或限制占用。两项都关闭不影响逐区域、逐页断点续跑。

运行中逐页处理，并非把整本书持续置于模型上下文；最终合并当前实现会把文本和 ZIP 读取到内存，插图很多时可能有额外峰值。超长区域尝试按空白行分割，若无法安全分割或表格/公式达到上限会报错停下，保留此前结果，不会假装完成。空白页判断和识别质量需人工复核。

监督器需要一直运行；关机、休眠、终止监督器或永久错误不会自行恢复。任务因进程崩溃中断后，监督器与模型服务恢复时尝试续跑；用户主动暂停的任务不会自动续跑。连续系统错误、磁盘满、页面损坏、无法解析或输出上限仍需人工处理。

## 故障排查

- **无法识别 GPU**：在 PowerShell 运行 `nvidia-smi`；检查驱动和 `runtime_new/` 是否安装齐全。页面上的 GPU 数字是监测值，不能单凭它证明每个区域都在 GPU 上执行；实际设备和加载问题请看 `model-server.log`。
- **模型启动失败**：检查模型和视觉投影文件、显存余量及运行时；确认 18499 端口未被其他服务占用。应用固定使用 7865（Web）及 18499（模型），均绑定 `127.0.0.1`。
- **下载失败**：先检查网络；模型可选 ModelScope 官方镜像。不要把未完成的 `.part` 文件改名当成完整模型。
- **任务停在 failed**：查看界面与 `app.log`。可修正原因后继续；改变页眉过滤条件需重新导入。不要手动修改已有的页面或分段文件。
- **无法跨电脑运行**：本仓库是源码和安装脚本，不是免安装分发包；须在目标电脑按本说明重新安装。尚未完成干净 Windows 电脑验证。
